# 인물 깊이 층 분리 고도화 (기획)

작성일 2026-09-15. 상태: 구현 완료(P1~P3), 실기기 검증은 `verification/person_depth_layers/REPORT.md` 참조. P4(선택)는 미착수.

## 한 줄 정의

인물 누끼 한 장에 붙어 있는 **연속 깊이 맵**을, 자세 랜드마크와 깊이 값을 함께 써서
**부위별 층(머리카락·얼굴·몸통·팔/손·손에 든 물건)** 으로 나누는 기기 내 후처리다.
결과는 층 지도 PNG 한 장과 층별 깊이 값이며, 셰이더는 층마다 다른 시차로 움직여
"카드 위 사진"이 아니라 "여러 겹의 종이 인형(레이어드 컷아웃)"처럼 보이게 한다.

외부 API를 호출하지 않는다. 사용하는 모델은 이미 앱에 들어 있는 Pose Landmarker Lite와
Depth Anything V2 Small INT8이다. 선택 단계에서만 MediaPipe 다중 클래스 셀피 세그멘터를 추가한다.

## 왜 필요한가 (현재 한계)

현재 `person_depth.frag`는 깊이 맵 한 장으로 인물 내부 픽셀을 `tilt × strength × (depth − 0.5)`
만큼 밀어낸다 (`lib/domains/ticket_viewer/widgets/person_depth_photo.dart`, 검증 기록
`verification/person_depth/REPORT.md`). 이 방식의 한계는 세 가지다.

| 한계 | 원인 | 사용자가 보는 것 |
| --- | --- | --- |
| 부위 간 분리감이 없다 | 깊이가 연속이라 손·얼굴·몸통이 거의 같이 움직인다 | 살짝 볼록한 스티커 느낌 |
| 강하게 하면 늘어진다 | 깊이 불연속(가슴 앞의 손, 얼굴 옆 머리카락)에서 한 장의 이미지를 워프하므로 경계가 번진다 | 손 가장자리가 고무처럼 늘어남 |
| 강도를 올릴 수 없다 | 위 번짐 때문에 최대 UV 이동을 0.026으로 묶어 두었다 | "우와"가 안 나온다 |

층 분리는 깊이를 **층 오프셋 + 층 내부 요철**로 분해한다. 층 오프셋은 크게, 요철은 작게 주면
분리감은 커지고 번짐은 사라진다. 실루엣·위치·크기·그림자 고정 규칙은 그대로 유지한다.

## 구현 언어 원칙

층 분리 후처리는 **Dart로 작성**한다. 네이티브(Kotlin)는 모델 추론과 그 결과 반환에만 쓴다.
이미 있는 추론 경로(MODNet 누끼, Depth Anything 깊이, Pose Landmarker 자세)는 그대로 두고,
Kotlin에는 `PersonProcessor.analyze`가 33개 랜드마크 좌표·가시성 배열을 반환값에 추가하는 것
한 가지만 바꾼다. 픽셀 배정·정리·층 지도 생성·저장은 모두 `lib/domains/depth/` 아래 Dart 코드가
백그라운드 isolate에서 수행한다. 이렇게 하면 데스크톱 단위 테스트로 층 지도 로직을 검증할 수 있고,
iOS 확장 시 네이티브 이식 범위가 추론으로 한정된다.

## 결과물 계약

제작 중 인물 맵(`people[i]`)에 아래 키가 붙고, 완성 시 `PersonDepthLayer`로 저장된다.

```json
{
  "personDepthPath": ".../person_depth_12.png",
  "partMapPath": ".../person_layers/1757900000.png",
  "parts": [
    {"label": "torso", "depth": 0.39, "share": 0.61},
    {"label": "head",  "depth": 0.55, "share": 0.17},
    {"label": "arms",  "depth": 0.62, "share": 0.10},
    {"label": "hands", "depth": 0.84, "share": 0.06}
  ],
  "layeredDepth": true
}
```

- `partMapPath`: 누끼와 같은 비율, 긴 변 320px의 PNG. **R·G·B = 먼 층 0·1·2의 가중치(0~255)**,
  가장 가까운 층은 `1 − R − G − B`로 유도하며 알파는 항상 255다. 알파를 쓰지 않는 이유는
  Flutter가 텍스처를 프리멀티플라이하기 때문이고, 가중치를 채널에 두면 선형 샘플링이 곧 페더가 된다.
  실루엣 바깥 3픽셀까지 가중치를 밀어내 외곽에서 "층 없음"으로 흐려지지 않게 한다.
  소장품 DB의 `person_layers` JSON에는 `part_map_key` 하나만 추가하면 된다.
- `parts[].depth`: 해당 층 픽셀들의 깊이 중앙값(0~1, 인물 내부 정규화 범위). 먼 층부터 정렬되며
  고정 가정(얼굴이 항상 앞)은 없다. `share`는 인물 픽셀 중 비중.
- 층이 1개이거나 자세가 없으면 `partMapPath = null`, `parts = []`이고 뷰어는 단일 깊이 셰이더를 쓴다.
  기존 소장품은 필드가 없으므로 자동으로 같은 경로를 탄다. 재분석은 하지 않는다 (완성 소장품 고정 규칙).

`PersonDepthLayer`에 `partMapPath`, `parts`, `layered`가 추가되었고 `usesPartLayers`가 셰이더 선택을
결정한다. `PersonDepthStrength`의 세 단계는 유지한다.

## 처리 순서 (Dart isolate, 기기 내)

입력은 이미 Dart에 도착하는 세 가지다: 누끼 PNG(`path`), 정렬된 깊이 맵 PNG(`personDepthPath`),
자세 분석 결과(`analysis`, 랜드마크 배열 추가). `creation_service.dart`의 `_preparePerson`에서
깊이 분석 직후 `PersonLayering.build()`를 `Isolate.run`으로 호출한다. 두 PNG를 `decodeImageFromList`로
읽어 `Uint8List` 픽셀로 다루고, 결과 층 지도는 `ui.Image.toByteData(format: png)`로 앱 문서 폴더에 저장한다.

1. **깊이 정렬** — 기존 Kotlin 결과를 그대로 사용. 누끼와 깊이 맵은 이미 같은 픽셀 격자다.
2. **부위 씨앗 만들기** — 33개 랜드마크로 부위 골격 선분을 만든다.
   머리: 코·눈·귀(0~10). 몸통: 어깨(11,12)–엉덩이(23,24) 사각형. 팔: 11–13–15, 12–14–16.
   손: 15~22 (손목·엄지·검지·새끼 끝). 다리: 23–25–27, 24–26–28. 랜드마크가 없는 부위는 씨앗을 만들지 않는다.
3. **픽셀 배정** — 작업 격자(긴 변 320)의 인물 픽셀마다 비용이 가장 낮은 부위를 고른다.
   `비용 = bias + (max(0, 골격까지 거리 − 코어) / 감쇠)² + λ × (픽셀 깊이 − 부위 깊이 중앙값)²`, λ = 8.
   코어·감쇠는 어깨 너비 비례(`PersonLayeringConstants`). 몸통 사각형만 bias 0.1을 가져 "나머지"를 맡고,
   같은 비용이면 손 → 팔 → 머리 → 몸통 순으로 이긴다. 팔뚝 캡슐은 팔꿈치에서 손목까지의 70%에서 끝나
   손목 주변은 손이 가진다. 1차는 거리만으로 배정해 부위별 깊이 중앙값을 배우고, 2차에 깊이 항을 더한다.
   깊이 항 때문에 "가슴 앞의 손"은 거리로는 몸통이어도 손에 붙고, 손보다 앞에 있는 물건도 손 층으로 온다.
4. **정리** — 확신 픽셀 30개 미만인 부위, 비중 2% 미만인 층, 이웃 층과 깊이 차이가 15/255 미만인 층은
   제거하고 다시 배정한다(같이 움직일 층은 나눌 이유가 없다). 5개 부위가 모두 살아 4층을 넘으면 깊이가
   가장 비슷한 이웃 중 작은 쪽을 병합한다. 3×3 페더 1회, 실루엣 밖 3픽셀 팽창.
5. **층 순서 결정** — 층별 깊이 중앙값으로 정렬. 최대 4층. 층이 1개만 남으면 분리 없음.
6. **머리카락/얼굴/옷 세분 (선택, 2단계)** — MediaPipe `selfie_multiclass_256x256`
   (배경·머리카락·몸 피부·얼굴 피부·옷·기타)를 돌려 3번 배정의 사전 확률로 쓴다.
   머리카락(뒤)과 얼굴(앞) 경계가 가장 깨끗해지는 부분이다. 추론만 Kotlin에서 돌려 클래스 지도 PNG를
   Dart로 넘기고, 사전 확률로 쓰는 계산은 Dart가 한다. 의존성 `tasks-vision 0.10.32`는
   이미 있고 모델 파일만 추가한다. 모델 크기·라이선스·SHA256은 `assets/models/README.md`에 기록.

자세 실패, 층 1개, 예외 어느 경우든 **오늘의 단일 깊이 결과는 그대로 반환**한다.
층 분리 실패가 입체감 자체를 끄지 않는다.

## 렌더링 (셰이더)

`shaders/person_layers.frag`. 샘플러 3개: 누끼, 깊이 맵, 층 지도. 유니폼 5~11번:
`uLayerGain`, `uReliefGain`, `uLayerCount`, `uLayerDepths(vec4)`.

```
층 k (먼 층 → 가까운 층, 최대 4, 상수 인덱스로 펼침):
  src  = uv − shift × (depth_k − 0.5) × uLayerGain          (shift = uTilt × uStrength × interior)
  src -= shift × (깊이맵(src) − depth_k) × uReliefGain      (층 내부 요철)
  w    = 층 지도(src)의 k번째 가중치 × smoothstep(0.5, 0.9, 누끼(src).a)
  color = mix(color, 누끼(src), w)
시작 color = 누끼 원본(변위 없음): 층 사이가 벌어진 곳은 원본이 남는다
```

- `uLayerGain = 3.0`, `uReliefGain = 0.5` (`ViewerConstants.personLayerGain/personReliefGain`).
  두 gain이 1이면 수식이 기존 셰이더와 같다. 즉 기존 결과는 이 셰이더의 특수한 경우다.
- "변위된 위치의 k번째 가중치"가 핵심이다. 변위된 위치가 다른 부위면 그 층은 그 픽셀을 그리지 않으므로
  깊이 불연속에서 이미지가 늘어지지 않는다. 가중치가 채널이라 경계는 선형 샘플링만으로 부드럽다.
- 겹침이 벌어져 빈 곳은 누끼 원본으로 메운다. 변위가 화면 폭의 1~3%라 잔상이 작다.
  더 깨끗한 채움(가까운 층 영역을 먼 층 색으로 밀어 넣은 backplate PNG)은 2단계 선택 사항.
- 실루엣 고정: 기존 `interior` 마스크(외곽 알파 침식 + 가장자리 감쇠)를 그대로 곱한다.
  손이 실루엣에 닿아 있으면 그 부근에서 손 층의 움직임도 0으로 줄어든다. 알파는 항상 원본 알파.
- 프리멀티플라이드 색 복원과 헤어 가장자리 처리는 기존 셰이더 주석의 방식을 유지한다.
- 셰이더 미지원, 층 지도 디코딩 실패, `layered = false`는 기존 `person_depth.frag`로 간다
  (`PersonDepthPhoto`가 층 지도 유무로 셰이더 에셋을 고른다).

## 제작 화면과 AI 항목

- **선택지**: `PersonDepthOptions`의 끄기·약하게·강하게는 그대로. 아래에 "부위별로 나누기" 스위치
  (`person-depth-layered`)가 층이 2개 이상 찾힌 인물에게만 보이고 기본은 켜기. 끄기를 고르면 비활성.
  부제로 "층 3개: 몸통·머리·손"처럼 찾은 층을 보여 준다.
- **미리보기**: 인물 배치 편집기의 틸트 미리보기에서 켬/끔을 바로 비교한다.
  완성 후에는 바꿀 수 없다 (완성 소장품 고정 규칙, 뷰어에 입체감 조작 없음).
- **제작 중 단계**: 층 분리는 인물 선택 직후 깊이 분석과 같은 단계에서 끝나므로 별도 진행 문구는 없다.
  실패해도 진행은 계속된다.
- **처리 정보**: `CreationService.layerNote` — "인물 1 층: 3개 (몸통·머리·손)", 사용자가 끄면
  "3개 찾음 · 사용자가 끔", 자세가 없으면 "자세 기반 분리 불가 · 단일 깊이".
- **문서의 AI 항목**: `README.md`의 "실제 AI 및 모델 파일"과 `docs/PROJECT_GUIDE.md` 모델 표에
  "인물 부위 층 분리" 행을 추가한다. 입력은 자세 랜드마크 + 정렬된 깊이, 출력은 층 지도 PNG + 층 깊이,
  모델은 기존 두 개(+ 선택 세그멘터). 사진은 기기 밖으로 나가지 않는다.

## 알려진 위험과 대응

- **두 사람 이상**: Pose Landmarker는 한 사람만 반환한다. 다른 사람 픽셀이 엉뚱한 층에 붙으면
  깊이 항이 걸러 주지만 완전하지 않다. 누끼 알파 성분이 2개 이상이면 층 분리를 끄고 단일 층으로 간다.
- **손이 얼굴 앞**: 깊이 차이가 작다. 골격 거리 항이 결정하므로 손 반경을 얼굴 반경보다 작게 잡는다.
- **옆모습·뒷모습**: 랜드마크 가시성이 낮아 층이 1~2개로 준다. 정상 동작이며 처리 정보에 남긴다.
- **헐렁한 옷·긴 머리**: 몸통과 머리카락 경계가 흔들린다. 선택 세그멘터가 해결하는 영역이라 2단계로 둔다.
- **잔상**: 층이 벌어진 자리를 원본으로 메우면 가까운 층의 색이 겹쳐 보일 수 있다. 변위를 화면 폭 3% 이내로
  묶고, 문제가 보이면 backplate 채움을 넣는다.
