# 공통 UI 기준

이 문서는 일반 앱 화면의 기준이다. 컬렉션의 티켓 감상·무대 효과는 별도 표현을 유지한다.
공통 컴포넌트 적용과 페이지별 정보 재배치는 순차적으로 진행한다.

## 치수와 스타일

- `AppMetrics`: 화면·카드 여백 16, 카드·입력·버튼 모서리 12.
- 주요/보조 버튼 최소 높이 52, 카드 내부 버튼 최소 높이 44.
- 검색창 최소 높이 48. 고정 높이 대신 글자 크기에 따라 늘어난다.
- 작은 간격 8, 섹션 간격 기본 24. 특수 화면의 밀도는 페이지 검수에서 조정한다.
- 브랜드 초록과 금액 강조 코랄은 유지한다. 오류·주의·성공은 `AppColors.error/warning/success`로 구분한다.
- 설명은 `textSecondary`, 비활성 요소만 `textDisabled`를 사용한다.

## 글자와 정렬

| 역할 | 스타일/정렬 | 길어질 때 |
| --- | --- | --- |
| 화면 제목 | headlineSmall 또는 AppBar titleMedium | 자연 줄바꿈, 컨테이너 높이 확장 |
| 목록 공연명 | titleSmall, 왼쪽 | 최대 2줄, 상세에서 전체 확인 |
| 상세·결제 공연명 | titleSmall, 왼쪽 | 전체 표시, 필요하면 라벨 아래로 이동 |
| 본문·안내 | bodyMedium/bodySmall, 왼쪽 | 자연 줄바꿈 |
| 좌석·일시·입장 정보 | bodyMedium, 왼쪽 | 말줄임 금지, 행 분리 |
| 금액 | titleSmall, 오른쪽 | 단위와 함께 표시, 좁으면 별도 행 |
| 버튼 | labelLarge, 가운데 | 문구 단축 우선, 필요한 경우 높이 확장 |

- 위젯마다 새 TextStyle을 만들기보다 `Theme.of(context).textTheme`에서 가져온다.
- 현재 번들 폰트가 없어 시스템 폰트를 유지한다. 특정 폰트로 통일하려면 한글 폰트 파일과 라이선스를 함께 포함한 후 테마에 등록한다.
- 화면 폭 하나에 맞춘 임의 개행, 공백을 이용한 정렬, 글자를 축소해서 맞추는 방식은 피한다.
- 여러 줄 설명 옆 아이콘은 첫 줄에 맞추고, 후속 줄은 설명의 시작점에 맞춘다.
- 긴 설명을 가운데 정렬하지 않는다. 짧은 완료/빈 상태 메시지는 가운데 정렬할 수 있다.
- 목록 카드의 제목을 2줄로 바꿀 때 같은 행의 날짜 시작 위치도 함께 맞춘다.

## 공통 컴포넌트

- `AppActionButton`: primary/secondary/destructive, compact, isBusy. 비활성에서도 버튼 종류를 유지한다. 부모가 고정 높이로 다시 제한하지 않는다.
- `AppSearchField`: 동일한 모서리·테두리·아이콘과 포커스 상태. 홈은 onSubmitted, 티켓·양도는 onChanged, 찜은 기존 컨트롤러 구독을 사용한다.
- 바쁜 버튼의 label은 호출자가 문맥에 맞게 전달한다. 결제 타이머를 별도 줄로 옮기는 일은 예매 흐름 작업에서 처리한다.

## 적용 범위와 다음 단계

이번 단계: 공통 테마·치수, 검색창 4종, 결제·티켓·양도 버튼을 공통화한다.
페이지별 카드·여백 값의 전환, 금액 단위, 상태 제목, 내비게이션, 소장품 표현은 후속 작업에서 적용한다.
홈 검색 입구도 공통 검색창과 같은 모양으로 맞춘다.

다음 브랜치 순서: 예매·내 티켓·QR → 양도 → 홈·찜·마이페이지·인증·컬렉션.
각 흐름은 320/375/430 논리 픽셀 폭, 글자 배율 1/1.3/2, 긴 한글·영문 공연명, 긴 장소·좌석명, 큰 금액으로 확인한다.
기본·로딩·실패·빈 목록·비활성 상태에서도 정보가 잘리거나 버튼이 겹치지 않아야 한다.
